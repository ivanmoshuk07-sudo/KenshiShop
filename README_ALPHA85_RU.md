# KenshiShop 0.3.0-alpha.85

Тестовая сборка: назначение жителей, служебные узлы, штатные роли. **Kenshi здесь не запускалась. Прежний сбой назначения города не считается устранённым до игрового теста.**

## Изменения

- Добавлено создание всех **72 оригинальных логических LocationNode**: бар 20, доспехи 12, оружие 15, инженерный 13, протезы 3, полиция 9. Всего 16 торговых, 46 охранных и 10 общих узлов. Исключены дубли бара. Координаты продавца доспехов взяты из соответствующего интерьера вместо оружейного.
- `HomeAssignment.lua` назначает тип жителя, обновляет здание отряда через штатный setter, выбирает текущий город Blackboard, только если он совпадает с городом назначенного здания, и вызывает `setHomeTown`. Сохранённый патруль, находящийся в другом городе, сохраняет город своего здания. Обновляется `StateBroadcastData.homeBuilding` каждого участника; собственность участников и `targetTown` проверяются чтением обратно.
- После существующей доставки сначала инициализируется ИИ участников, затем назначается дом, создаются узлы и устанавливается окончательный пакет работы. Запрашивается пересчёт GOAP. Инициализация участника больше не вызывается после установки рабочего пакета.
- Торговцы используют оригинальные задачи Shopkeeper (20) и открытия магазина (86) с оригинальным `targeting=0`. Бар и протезы работают круглосуточно; остальные — 06:00–23:00, ночью получают штатный уход домой/сон.
- Охрана получает задачу 268 с оригинальными настройками выбора внутреннего поста. Начальник — охрану домашнего здания 38. Патрульный лидер — оригинальную Patrol hometown (36), участники сохраняют штатное поведение отряда и экстренную помощь. Прежний WANDER_TOWN (37) заменён. Защита союзников ограничена штатной задачей 288. Гарантия «никогда не пересекать ворота» не заявляется.
- Medic, Robotics, Rescue и выдача аптечек/ремкомплектов сохранены. Начальный пакет нового отряда содержит экстренную помощь, рабочий назначается после прибытия. Успешный переход выполняется один раз за сеанс контроллера. Перепризыв существующих NPC и постоянные команды движения к постам не добавлены.
- При переходе с KS84 ассортимент принудительно не обновляется. Файлы ассортимента, данные качества, мебель, планировки и совместимость не изменены.

## Основания и ограничения

Схема API изучена в [Squad Autonomy](https://github.com/Au2942/KenshiPlugins/blob/c15918165add78a1a424c01967b200b4d3128394/SquadAutonomy/src/SquadAutonomy.cpp#L637-L683) и [назначении его домашних зданий](https://github.com/Au2942/KenshiPlugins/blob/c15918165add78a1a424c01967b200b4d3128394/SquadAutonomy/src/SquadAutonomySettings.cpp#L524-L563). Для наших NPC написана своя процедура через KenshiLua. Обходы ограничений фракции игрока не перенесены: служащие относятся к отдельной NPC-фракции. Устанавливать Squad Autonomy для этой сборки не требуется.

Настройки задач сверены с присланными ванильными базами, координаты — с присланными интерьерами. Источники и контрольные суммы сохранены в `Development/references`. Нулевые веса обычных задач допустимы: они встречаются в оригинальном Shop-24hr; прежнее общее утверждение об их ошибочности неверно.

Если штатный setter не установит город, работа блокируется после трёх ошибок. Проверка не отключена, запись сырого указателя вместо назначения не используется. Лог показывает ожидаемый и фактический город, `isMyTown`, источник города и текст ошибки. При неподготовленной собственности или городе переход ожидает загрузки.

KenshiLua возвращает LocationNode как непрозрачный указатель. Входные координаты, повороты, типы и номера этажей сверены с оригиналом. При создании передаются здание и мировые координаты; назначение этажа и доступность постов определяет движок. Прочитать состояние созданного узла через этот API нельзя. Кэш учитывает смену физического узла здания, но удаление/восстановление узлов при выгрузке зоны и сохранении/загрузке требует игрового теста.

## Установка и проверка

Полностью закройте Kenshi. Сохраните копию сохранения и прежней папки мода. Из полного архива замените `mods/KenshiShop` целиком. `KenshiShop_LegendaryCompat` включайте только с Legendary of Kenshi. KenshiLua остаётся установленной отдельно.

Загрузите копию существующего сохранения. Перепризывать NPC не требуется. Сначала проверьте один магазин, затем остальные роли, смену времени суток и сохранение/загрузку. Отдельно проверьте возвращение в город после выгрузки зоны, реакцию на нападение и медицинскую помощь.

Диагностика:

- `NPC_HOME85 ... verified=true` — город, тип жителя и ссылки на здания проверены.
- `NPC_NATIVE_NODES85 ... count=... selection=UNVERIFIED` — вызовы создания и привязки узлов завершились; выбор поста NPC ещё не подтверждён.
- `NPC_ROLE_READY ... KS85 ... gameplay=UNVERIFIED` — рабочий пакет назначен и проверен.
- `NPC_ROLE_FAIL ... HOME_ASSIGN ...` — назначение дома не прошло; полного рабочего ИИ в таком случае нет.
- `KS.npcStatus(index)` показывает текущие задачи движка. Название пакета само по себе не доказывает работу роли.

Локально проверены синтаксис 104 игровых Lua-файлов, 36 сценариев с тестовыми объектами API и отдельный сценарий восстановления контроллера, воспроизводимость .mod, точное совпадение 72 записей узлов с исходными данными, сохранность двоичных данных мебели/ассортимента и 39 защищённых файлов зданий, мебели, планировок, ассортимента и совместимости. Эти проверки не исполняют ИИ Kenshi.
