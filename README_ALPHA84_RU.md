# KenshiShop 0.3.0-alpha.84

Тестовая переработка ИИ, ассортимента бара и качества доспехов по замечаниям к alpha.83. Расстановка мебели и физические модули зданий не изменены.

## Установка полного мода

Закройте Kenshi и сохраните копию сохранения и папки мода. Из полного архива установите `KenshiShop` в `mods`, заменив прежнюю папку `mods/KenshiShop` целиком. Требования к KenshiLua прежние. `KenshiShop_LegendaryCompat` включайте только вместе с Legendary of Kenshi. Загрузите копию сохранения с закрытым торговым окном; перепризывать NPC не требуется.

При переходе старых отрядов на KS84 снимаются только помеченные этим модом цели движения, удержания позиции и точечного нападения из alpha.82/.83. Сторонние приказы не очищаются, переход откладывается на время боя, лечения, переноски раненого или активного приказа. Старый товар торговца один раз обновляется штатным механизмом после безопасного перехода. При обычной загрузке уже обновлённого сохранения повторного принудительного обновления нет.

## ИИ

Удалён рабочий Lua-цикл выдачи координат постов, обход дверей по кругу, повторный `setDestination` при простое и поиск целей для принудительного `Focused Melee Attack`. `Duty.lua` теперь только читает текущую задачу движка. Конечная доставка нового отряда к зданию сохранена; после неё управление передаётся штатным FCS-задачам.

- Торговец получает `STAND_AT_SHOPKEEPER_NODE` и штатное открытие магазина. Бар и протезы работают круглосуточно, остальные продавцы — с 06:00 до 23:00, с задачей отдыха ночью.
- Охранники и начальник используют `STAND_AT_GUARD_NODE_HOMEBUILDING_INDOORS_ONLY`, защиту своего отряда и `PROTECT_ALLIES_STAY_IN_TOWN`. Конкретный пост и переход в бой выбирает движок.
- Патруль: лидер получает штатное городское перемещение `WANDER_TOWN` (37), остальные — `FOLLOW_SQUADLEADER` (141), с штатным выбором движения и построения. Защита союзников ограничивается задачей `PROTECT_ALLIES_STAY_IN_TOWN` (288). Проверяются и при необходимости исправляются домашний город каждого участника, домашний город отряда и `Blackboard.targetTown`.
- Medic/Robotics/Rescue сохранены. У обычных задач теперь положительные веса; нулевой вес сохранён у срочных конечных задач. Вес 0 у бесконечной обычной работы был неверным срочным переопределением.

Для работы у прилавка и на постах создаются настоящие служебные `LocationNode` через специальный метод `createLocationNode`. Это логические узлы штатного ИИ, без модели, коллизии и создания `Building`. Используются координаты ранее имевшихся постов и оригинальные шаблоны узлов. Они привязываются к своему зданию через штатный API usage nodes. Продавец и отдельный отряд охраны используют один набор. Созданные узлы отмечаются в текущем сеансе; частичный сбой привязки не пересоздаёт уже созданные узлы. После трёх ошибок настройка останавливается с диагностикой.

Это собственные FCS-пакеты на штатных задачах Kenshi. Полное копирование контракта наёмников не заявляется. Патруль больше не получает вручную сгенерированные точки; маршрут строит движок. Фактическое прохождение ворот и границы городского поведения необходимо проверить в игре. Строгая геометрическая гарантия, что NPC никогда не пересечёт ворота, не подтверждена. Создание узлов, их жизненный цикл при выгрузке/загрузке зоны и выбор конкретных постов также требуют проверки внутри Kenshi: возвращаемый `LocationNode` доступен в KenshiLua только как непрозрачный указатель.

## Ассортимент

**Бар.** В двоичных данных теперь есть оба оригинальных списка: `Bar` (`1973-gamedata.base`) и `medical and travel supplies` (`44862-rebirth.mod`). Второй включает аптечки, шины, ремкомплекты, инструменты, спальники, походные рюкзаки, карты и чертежи палаток. При доступности используется полный профиль бара Края Мира (`58699-rebirth.mod`), включая текущие изменения другими модами и дополнительные барные списки. Если профиль недоступен, оба основных списка всё равно обязательны. Конкретный набор и количество при каждом пополнении выбирает обычная генерация Kenshi.

**Доспехи.** Ассортимент по-прежнему берётся у Короля Брони. Исправление касается качества: веса теперь постоянно заданы в собственной торговой фракции `400-KenshiShop.mod`, в файле мода и в текущих игровых данных этой фракции. Они действуют и при самостоятельном обновлении товара движком. Временная подмена весов только на время вызова обновления удалена.

Базовые относительные веса: прототип 0, низкое 0, стандарт 2, высокое 80, специалист 110, мастерское 50. Это профиль оригинальной фракции Skeletons, к которой относится Король Брони. В игре считывается её текущий профиль `42088-rebirth.mod`, с учётом других модов. Оригинальная фракция Skeletons не изменяется. Веса общие для торговой фракции мода, поэтому применяются к любой броне в её магазинах; это соответствует также источнику оружейного магазина Scraphouse. Это не гарантия мастерского качества у каждого предмета.

Оружейный, инженерный и магазин протезов сохраняют подбор источников alpha.83.

## Проверки и диагностика

Локально проверены синтаксис 103 Lua-файлов, 27 поведенческих сценариев с имитацией API, сценарий восстановления контроллера, структура `.mod`, штатные enum задач и сохранность физической мебели/зданий. Отдельно проверено отсутствие команд движения при многократном рабочем аудите, отсутствие повторного создания успешно созданных узлов и сохранение весов качества после возврата из функции. Это проверки кода и API-границ, не запуск движка Kenshi.

- `NPC_NATIVE_NODES84` — вызовы создания и привязки служебных узлов завершились; не является подтверждением выбора узла NPC.
- `NPC_ROLE_READY ... KS84` — пакет назначен; не является подтверждением успешной работы всей роли.
- `NPC_ROLE_WAIT_NODES` — настройка узлов ещё не завершена или API отверг вызов. Телепортации или возврата к циклическим командам при этом нет.
- `NPC_CATALOG84` — выбранный источник товара и фактические веса качества фракции.
- `NPC_CATALOG84_MIGRATED` — однократный вызов обновления старого ассортимента.
- `duty=NATIVE_TASK_...` в `KS.npcStatus(index)` показывает реальную текущую задачу движка; старые статусы `MOVING_TO_POST`/`AT_POST` этой версии не выдаются.
